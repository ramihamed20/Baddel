# بدّل — Baddel

موقع بسيط لتبادل شعب وقروبات الطلبة. **الطالب لا يحتاج حسابًا ولا ينتقل إلى GitHub**: ينشر طلبه مباشرة، يشوف طلبات الآخرين، يختار الشعبة والقروب الحالي والمطلوب، ويضغط للتواصل على تيليجرام.

## الوظائف

- شعبة A وB، وفي كل واحدة 8 قروبات: A1, A2, B1, B2, C1, C2, D1, D2.
- طلبات عامة يقرأها الجميع، ونشر طلب مباشر من نموذج الموقع.
- بحث حسب الشعبة والقروب «من → إلى»، مع إمكانية عكس اتجاه البحث.
- مطابقة تلقائية للطلبات المتعاكسة حتى بين الشعبتين.
- رابط Telegram مباشر لصاحب كل طلب.
- «طلباتي» وحذف الطلب باستخدام مفتاح سري محفوظ محليًا على نفس المتصفح.
- انتهاء الطلب تلقائيًا بعد 30 يومًا.

## الاستضافة

- **GitHub Pages**: يستضيف `index.html` و`styles.css` و`app.js` و`config.js` و`favicon.svg`.
- **Supabase** (مشروع مستقل): قاعدة بيانات PostgreSQL ودالة Edge Function عامة تستقبل طلبات الطلبة دون تسجيل دخول. لا حاجة إلى VPS أو GitHub Issues.
- يجب تهيئة Supabase وربطه قبل أن تعمل الطلبات للزوار. **الكود موجود ولكن الخدمة ليست متصلة حاليًا.**

### تجهيز Supabase (لم يتم تنفيذه بعد)

1. إنشاء مشروع Supabase **مستقل** باسم Baddel، وليس ضمن قاعدة بيانات PlusCard أو Lockin.
2. تنفيذ ملف `backend/schema.sql` في SQL Editor؛ يفعل RLS ويمنع الوصول المباشر للجداول عبر مفتاح عام.
3. نشر ملف `backend/baddel-api/index.ts` كـ Edge Function باسم `baddel-api` مع `verify_jwt=false`، حتى يمكن لأي طالب نشر الطلب بدون حساب.
4. وضع عنوان الدالة العام في `config.js`:
   `window.BADDEL_API_URL = "https://PROJECT_REF.supabase.co/functions/v1/baddel-api";`
5. التأكد من نشر واجهة GitHub Pages من فرع `main` وجذر `/(root)` عبر [Settings → Pages](https://github.com/ramihamed20/Baddel/settings/pages).

> **لا تضع** Supabase service_role أو secret key في `config.js` أو `app.js`؛ دالة Edge Function فقط تحصل على سر قاعدة البيانات عبر إعدادات الخادم.

رابط GitHub Pages بعد تفعيله: **https://ramihamed20.github.io/Baddel/**

## الخصوصية والحماية

- اسم مستخدم Telegram وبيانات التبديل **عامة** لكل زائر؛ تطلب الواجهة موافقة الطالب قبل النشر.
- لا نخزن رقم هاتف أو بريد إلكتروني. لا توجد حسابات للطلبة.
- حذف الطلب ممكن من **نفس المتصفح** الذي نشر منه فقط، لأنه يحتفظ بمفتاح حذف سري في `localStorage`. مسح بيانات المتصفح قد يُفقد إمكانية الحذف.
- قاعدة البيانات تخزن تجزئة مفتاح الحذف فقط، وليس المفتاح نفسه. لا تملك الواجهة صلاحيات مباشرة على الجداول.
- API يتحقق من المدخلات، ويحد طلبات النشر إلى 8 تقريبًا لكل عنوان IP في الساعة، ويحجب مصادر المتصفح غير المسموح بها. قد يلزم CAPTCHA أو ضوابط أقوى إذا حدث إغراق متعمد.
- طلبات المستخدمين تنتهي صلاحيتها بعد 30 يومًا. خدمة API تنظف الطلبات المنتهية عند نشر طلب جديد؛ قد تستمر الصفوف منتهية الصلاحية مخزنة حتى عملية التنظيف. يظل التبديل الفعلي من مسؤولية الطلبة والجامعة.

## تطوير محلي

```bash
python3 -m http.server 8000
```

افتح `http://localhost:8000/`. موقع الويب ثابت ولا يحتاج Python كخلفية؛ هذا الخادم فقط لتقديم الملفات أثناء التطوير، ويحتاج إعداد Supabase لعرض بيانات حقيقية.

## بنية الملفات

- `index.html` — واجهة RTL.
- `styles.css` — التصميم المتجاوب.
- `app.js` — نشر/قراءة/بحث/تطابق/حذف الطلبات.
- `config.js` — عنوان API العام.
- `backend/schema.sql` — الجداول وسياسة وصول صارمة.
- `backend/baddel-api/index.ts` — Supabase Edge Function بمفتاح DB سري على الخادم، وليس لدى الطالب.
